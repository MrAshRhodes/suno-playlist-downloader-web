## Overview

v2.1 delivers per-song selection before download, improved @username input discovery, and security housekeeping. All changes are client-side only — zero functional regressions to download flows or backend API routes.

## Phases

### Phase 12: Per-Song Checkbox Selection

**Goal**: Users can select individual songs before downloading — opt-out model, all selected by default
**Depends on**: Nothing (self-contained UI change in song table)
**Requirements**: SEL-01, SEL-02, SEL-03, SEL-04, SEL-05
**Plans**: 1 plan

Plans:
- [x] 12-01-PLAN.md — Selection state, checkbox column, download filter, and button label

**Success Criteria (all met):**
1. Each song row has a visible checkbox that toggles selection
2. Header checkbox selects all / deselects all / shows indeterminate when partial
3. Download button reads "Download N songs as ZIP" (singular at N=1)
4. Download button disabled at zero selection
5. All songs checked on load (opt-out model)

**Key decisions:**
- Used plain HTML `<input type="checkbox">` with ref callback for indeterminate — prod App uses plain HTML, not Mantine
- `selectedIds as Set<string>` keyed on clip.id — O(1) has() lookup
- Captured `e.currentTarget.checked` before functional updater — avoids React synthetic event null dereference
