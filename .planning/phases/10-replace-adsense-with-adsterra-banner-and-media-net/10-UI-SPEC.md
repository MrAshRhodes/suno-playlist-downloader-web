# Phase 10 — UI Design Contract

> Visual and interaction contract for the Adsterra banner integration, FTC "Advertisement" label, and `/privacy` policy route. Generated by gsd-ui-researcher; verified by gsd-ui-checker.

**Phase scope:** Replace blocked AdSense with one Adsterra 728x90 banner above the footer, add an FTC-compliant "Advertisement" label, build a `/privacy` route hosting the Iubenda widget, and add a "Privacy Policy" footer link. Visual/integration only — no functional regressions.

**Existing aesthetic to preserve:** Monolith dark-first design language; dark navy/purple (`#7B5EA7`) primary accent + cyan (`#00C8FF`) secondary accent; 24px-radius `.monolith-card` surfaces; Inter font; CSS-variable-driven theming with `dark-mode`/`light-mode` classes on `:root`.

## Spacing Scale

Declared values (multiples of 4 only):

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | Gap between Advertisement label and AdSlot wrapper top edge (label sits flush with 4px breathing room) |
| sm | 8px | Privacy page paragraph spacing inside Iubenda embed container |
| md | 16px | AdSlot inner padding (between border and iframe); Privacy page section padding |
| lg | 24px | Privacy page top/bottom container padding; gap between Privacy heading and Iubenda widget |
| xl | 32px | AdSlot vertical margin (above + below) — `margin: 32px auto`, matches Phase 4 D-03 |
| 2xl | 48px | Privacy page outer top margin (matches existing `.app-footer` `margin-top: 48px`) |

**Exceptions:**
- AdSlot wrapper border-radius is `12px` — explicit half-step from `.monolith-card`'s `24px`. Rationale: visually subordinate the ad as a "different element class" (per CONTEXT.md locked decision + research Pitfall 4). 12px is allowed as a non-spacing radius token even though it is not a multiple of 4 spacing — it is a corner-radius scale value, not a spacing value.
- Mobile-only optional `margin: 24px auto` on `.app-ad-slot` `@media (max-width: 768px)` — accepted compromise per research §9.6 (728x90 overflows phones; we keep desktop-only).

## Component Inventory

### 1. AdSlot (`client/src/components/AdSlot.tsx`)

**Type:** Functional React component, plain `<div>` (NOT Mantine `<Card>` — locked decision).

**Props:**
```ts
interface AdSlotProps {
  adKey: string;        // Adsterra unit key from VITE_ADSTERRA_UNIT_KEY env
  width: number;        // 728 for desktop leaderboard
  height: number;       // 90 for desktop leaderboard
  className?: string;   // optional layout hook (e.g. "app-ad-slot")
}
```

**Render contract:**
```tsx
<div
  ref={ref}
  className={className}
  style={{
    minHeight: height,                          // CRITICAL: CLS reservation
    width,
    margin: '32px auto',
    padding: 16,
    border: '1px solid var(--border-color)',
    borderRadius: 12,
    background: 'transparent',
  }}
/>
```

**State diagram:**

| State | Trigger | Visual |
|-------|---------|--------|
| `empty-key` | `adKey` is falsy / empty string (env var unset) | Empty wrapper rendered: 728x90 box with the border ring + transparent background visible. NO label, NO error message, NO retry button. Reserves layout space so footer position is identical to fully-loaded state. |
| `loading` | `adKey` truthy; `useEffect` has fired; iframe not yet inserted by Adsterra invoke.js | Same empty wrapper. Browser may show iframe placeholder skeleton — this is fine, no custom skeleton needed. |
| `loaded` | Adsterra invoke.js has appended an `<iframe>` into the wrapper div | Advertiser creative renders inside the iframe, contained by the 12px border + 16px padding. |
| `blocked` (ad-blocker) | uBlock/etc cancels invoke.js network request | Wrapper renders empty (same as `empty-key`). NO "ad-block detected" message — explicitly forbidden per research §7 + Phase 4 D-09 (graceful degradation). |
| `script-error` | invoke.js loads but errors | Same as `blocked` — empty wrapper, silent failure. Browser console will show the error; no user-visible UI change. |

**Critical:** Across ALL states the wrapper retains its `minHeight: 90` reservation. This is the ONLY way to guarantee CLS < 0.1 (research Pitfall 2).

**Interaction:** Zero. AdSlot is non-interactive at the wrapper level. Clicks pass through to the iframe (advertiser owns click handling). Wrapper has no hover/focus state.

### 2. AdvertisementLabel (inline in `App.tsx`, no separate component)

**Type:** Plain `<div>` rendered immediately above each `<AdSlot>`.

**Render contract:**
```tsx
<div
  style={{
    width: 728,
    margin: '0 auto 4px',
    fontSize: 11,
    fontWeight: 400,
    color: 'var(--text-muted)',
    textAlign: 'center',
    lineHeight: 1,
    letterSpacing: '0.06em',
  }}
>
  Advertisement
</div>
<AdSlot adKey={...} width={728} height={90} className="app-ad-slot" />
```

**Why inline (not a component):** Single use site, one ad slot per page (research §6 "Key constraint" — single ad until 5K sessions/mo). Inline avoids the indirection cost. If a second ad slot is added later, hoist into `<AdLabel>` component then.

**FTC compliance rationale:** Overrides Phase 4 D-13 ("no label"). Per research §13 Q2 + Adsterra EU policy + FTC 16 CFR §255.5, paid placements visible to US/EU traffic must carry an "Advertisement" disclosure. The 11px muted-grey style is the minimum-disruption form that satisfies disclosure norms while preserving Monolith aesthetic.

### 3. Privacy page (`client/src/pages/Privacy.tsx`)

**Type:** Functional React component. Mantine `<Container>` wrapper for max-width + centering. Plain `<div className="monolith-card">` content surface for visual consistency. Iubenda script + embed div per their standard pattern.

**Layout structure:**
```
<Container size="md" px="md" py="xl">      <!-- 768px max-width, 16px h-padding, 32px v-padding -->
  <a href="/" className="back-to-home">    <!-- IconArrowLeft + "Back to downloader" -->
    ← Back to downloader
  </a>
  <h1 className="section-heading">         <!-- 20px / 600 / -0.02em letter-spacing -->
    Privacy Policy
  </h1>
  <div className="monolith-card privacy-content">  <!-- 24px radius card holding embed -->
    <a href="https://www.iubenda.com/privacy-policy/{IUBENDA_DOC_ID}"
       className="iubenda-white iubenda-noiframe iubenda-embed iubenda-noiframe"
       title="Privacy Policy">
      Privacy Policy
    </a>
    <!-- Iubenda loader script appended via useEffect -->
  </div>
</Container>
```

**`.privacy-content` styling:**
- `padding: 24px` (Mantine `lg` token — matches `.step-card` padding)
- `min-height: 400px` (reserves space while Iubenda widget loads → CLS guard)
- Standard `.monolith-card` 24px radius + border + shadow

**`.back-to-home` link styling (matches existing `.app-footer a` pattern):**
- `color: var(--accent)`
- `text-decoration: none`
- `font-size: 13px`
- `display: inline-flex` + `align-items: center` + `gap: 6px`
- `margin-bottom: 16px`
- `transition: opacity 0.2s ease`
- `:hover { opacity: 0.75 }`
- Icon: `<IconArrowLeft size={16} />` from @tabler/icons-react

**Iubenda widget mount (in `useEffect`):**

The component appends a single `<script>` tag whose body uses Iubenda's standard async-loader pattern (queue a function that injects `https://cdn.iubenda.com/iubenda.js` after window load). Component-scoped lifecycle: appended on mount, removed on unmount. Reference Iubenda's official embed snippet from their dashboard at integration time — do not hand-edit their boilerplate.

**Mount lifecycle:** Iubenda script lives ONLY on `/privacy` — mounted via component-scoped `useEffect`, unmounted on route change. Keeps cookies/tracking off the main download flow (locked CONTEXT decision).

**Theme support:** Privacy page renders identically to home in both themes — uses CSS variables for all surfaces, text, borders. Iubenda embed iframe internal content is white in dark mode (cross-origin, cannot restyle). Quarantine pattern (24px-radius card + 24px padding) makes the brightness gap deliberate, not jarring.
