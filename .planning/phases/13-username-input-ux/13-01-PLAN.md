```typescript
    // Check if this is a username (starts with @ or doesn't look like a URL)

        throw new Error("Invalid URL or no playlist ID found")
```

getSongsFromUser signature (lines 67–70):
```typescript
static async getSongsFromUser(username: string): Promise<[IPlaylist, IPlaylistClip[]]> {
    const cleanUsername = username.startsWith('@') ? username.slice(1) : username;
    const response = await fetch(`${API_BASE}/playlist/user/${cleanUsername}/songs`);
```

NOTE: getSongsFromUser expects a plain username string (with or without leading @).
Passing a full URL like "https://suno.com/@focusedbeats" produces cleanUsername = "https://suno.com/@focusedbeats"
and a broken fetch target. The username MUST be extracted before calling getSongsFromUser.

Current code (lines ~38–41):
```typescript
    if (url.startsWith('@') || (!url.includes('http') && !url.includes('playlist') && !url.includes('.'))) {
        return this.getSongsFromUser(url);
    }

    // Extract Playlist Id
```

After the closing `}` of the existing `if` block and before the `// Extract Playlist Id` comment, insert:
```typescript
    // Route full suno.com/@username URLs to getSongsFromUser
    const usernameUrlMatch = url.match(/suno\.com\/@([^/?#]+)/);
    if (usernameUrlMatch) {
        return this.getSongsFromUser(usernameUrlMatch[1]);
    }
```

The new routing order becomes:
1. Bare `@username` or non-URL string → `getSongsFromUser(url)` (existing)
2. Full `https://suno.com/@username` URL → `getSongsFromUser(usernameUrlMatch[1])` (new)
3. Playlist regex → playlist fetch (existing)
4. Throw "Invalid URL or no playlist ID found" (existing)

IMPORTANT: Pass `usernameUrlMatch[1]` (the captured username, e.g. `"focusedbeats"`) — NOT the full URL. `getSongsFromUser` does not parse URLs; passing the full URL will produce a broken fetch request.
