# Phase 11 Plan 04: web-version/client Vite Patch + Rebuild public/

## Meta
- **Phase:** 11
- **Plan:** 04
- **Requirements:** SEC-06, SEC-07
- **Depends on:** none
- **Estimated complexity:** low

## Objective
Upgrade `vite` from `6.3.3` to `^6.4.1` in `web-version/client` (closes alerts #2, #20, #21, #22 per SEC-06) and rebuild `public/` so the patched bundle is what Replit serves (per project memory: "Always rebuild public before pushing"). Preserve TypeScript/Vite build per SEC-07.

## Context
Vite `6.3.3 → 6.4.1` is a minor patch within v6 — no breaking config changes expected (per D-06). Pre-research confirmed `web-version/client` is on vite 6.3.3. Per D-08 we do NOT regenerate the lockfile from scratch — only targeted install. Per D-07 we run `npm run build` and verify output. Discretion item: check if `@vitejs/plugin-react` needs a coupled bump — only act if peer-dep warning surfaces.

## Tasks

### Task 1: Targeted vite upgrade
**Type:** execute
**Files:**
- `web-version/client/package.json` — bump vite version
- `web-version/client/package-lock.json` — regenerated targeted entries

**Steps:**
1. Run `cd web-version/client && npm install vite@^6.4.1` (per D-06, D-08 — targeted, no full reinstall)
2. Verify `web-version/client/package.json` shows `"vite": "^6.4.1"` in `devDependencies`
3. Run `cd web-version/client && npm ls vite` — confirm resolved version `>=6.4.1`
4. Check for peer-dep warnings about `@vitejs/plugin-react`. If a warning appears, run `cd web-version/client && npm install @vitejs/plugin-react@latest` and re-verify

**Verification:**
- [ ] `web-version/client/package.json` `devDependencies.vite` is `^6.4.1` (or higher)
- [ ] `npm ls vite` shows `>=6.4.1`
- [ ] No unresolved peer-dep warnings on install

### Task 2: Run client build and verify bundle
**Type:** execute
**Files:**
- (read-only verify) `web-version/client/vite.config.ts`
- `public/` — rebuilt bundle output

**Steps:**
1. Run `cd web-version/client && npm run build`
2. Confirm exit code 0 — build must succeed (per D-07)
3. Verify build output exists. Check both possible output locations (depends on vite config):
   - `web-version/client/dist/` (default vite output)
   - `public/` (if `build.outDir` is configured to point there, or if `deploy.sh` copies dist→public)
4. Read `web-version/client/vite.config.ts` to confirm `build.outDir` setting
5. If output is `dist/` and `deploy.sh` exists, run `bash deploy.sh` from repo root to copy `dist/ → public/`
6. If output is directly `public/`, no copy step needed
7. Verify `public/index.html` exists and contains a `<script type="module">` reference to a hashed JS asset (sanity check that bundle was rebuilt, not stale)
8. Confirm `public/index.html` mtime is fresh (within last few minutes)

**Verification:**
- [ ] `npm run build` exits 0
- [ ] `public/index.html` exists and references hashed JS bundle
- [ ] `public/index.html` mtime is recent (rebuilt this session)
- [ ] No build errors related to vite 6.4.x API changes

### Task 3: Audit verification
**Type:** execute
**Files:**
- (read-only) `web-version/client/package-lock.json`

**Steps:**
1. Run `cd web-version/client && npm audit --json`
2. Confirm zero findings for `vite` (jq filter: `jq '.vulnerabilities.vite'` returns `null`)
3. Capture full audit output for the SEC-09 closure step in 11-05

**Verification:**
- [ ] `npm audit` in `web-version/client/` reports no findings for `vite`
- [ ] No HIGH/MEDIUM findings introduced by the upgrade
