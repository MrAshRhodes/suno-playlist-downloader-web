# Phase 11 Plan 02: web-version multer Audit + Remove or Upgrade

## Meta
- **Phase:** 11
- **Plan:** 02
- **Requirements:** SEC-03, SEC-08
- **Depends on:** none
- **Estimated complexity:** low (audit confirms unused) | medium (if usage found)

## Objective
Audit `multer` usage across `web-version/server.js` and `web-version/routes/`, then EITHER remove `multer` from `web-version/package.json` (if unused — pre-research confirmed empty grep) OR upgrade to `^2.0.2` and adapt breaking API changes (if usage exists). Closes 4 high-severity alerts (#23, #24, #25, #27) per SEC-03 while preserving all server behavior per SEC-08.

## Context
Pre-research grep for `multer` across `web-version/server.js` and `web-version/routes/` returned EMPTY. `web-version/package.json` lists multer as "optional for potential future uploads" but no code uses it. Per planning rule 9: if confirmed unused, remove entirely (simpler and safer than upgrading an unused dep). Per D-03 we must still re-audit during execution to confirm the pre-research finding remains accurate. Per D-04/D-05 if any usage is found, we upgrade to `multer@^2.0.2` and fix breaking changes (file filter callback signature, error class names, storage engine interface).

## Tasks

### Task 1: Audit multer call sites
**Type:** execute
**Files:**
- (read-only) `web-version/server.js`
- (read-only) `web-version/routes/*.js`
- `.planning/phases/11-security-check-review-dependabot-alerts-and-address-each-ale/11-02-multer-audit.md` — audit findings

**Steps:**
1. Run `grep -rn "multer" web-version/server.js web-version/routes/ web-version/utils/ 2>/dev/null` and capture all matches
2. Run `grep -rn "require.*multer\|from ['\"]multer['\"]" web-version/ --include="*.js" 2>/dev/null` for any import sites
3. Run `grep -rn "upload\.\(single\|array\|fields\|none\|any\)\|\.upload(" web-version/ --include="*.js" 2>/dev/null` for usage of multer's middleware API
4. Write findings to `11-02-multer-audit.md` with:
   - Header: `# multer Audit (Phase 11-02)`
   - Section "Grep Results": each command and its raw output
   - Section "Conclusion": one of `UNUSED — safe to remove` OR `USED at <file:line> — upgrade required`
5. If conclusion is `UNUSED`, proceed to Task 2 (Removal Branch)
6. If conclusion is `USED`, skip Task 2 and proceed to Task 3 (Upgrade Branch)

**Verification:**
- [ ] `11-02-multer-audit.md` exists with all three grep commands and outputs
- [ ] Conclusion line is unambiguous (`UNUSED` or `USED`)

### Task 2: Removal branch (if UNUSED)
**Type:** execute
**Files:**
- `web-version/package.json` — remove multer from dependencies
- `web-version/package-lock.json` — regenerated

**Steps:**
1. Run `cd web-version && npm uninstall multer`
2. Verify `multer` is no longer present in `web-version/package.json` (`grep -c '"multer"' web-version/package.json` returns 0)
3. Run `cd web-version && npm ls multer` — must report `(empty)` or that multer is not installed
4. Run `cd web-version && npm audit --json` and confirm zero findings for `multer` (jq filter: `jq '.vulnerabilities.multer'` returns `null`)
5. Run `cd web-version && npm start` (or equivalent) and confirm server boots without errors; kill after 5s

**Verification:**
- [ ] `grep -c '"multer"' web-version/package.json` returns 0
- [ ] `npm ls multer` from `web-version/` shows multer absent
- [ ] `npm audit` from `web-version/` reports no multer findings
- [ ] Dev server boot smoke test passes (no `Cannot find module 'multer'` errors)

### Task 3: Upgrade branch (if USED — only run if Task 1 found usage)
**Type:** execute
**Files:**
- `web-version/package.json` — bump multer to `^2.0.2`
- `web-version/package-lock.json` — regenerated
- `web-version/server.js` and/or `web-version/routes/*.js` — adapt breaking changes

**Steps:**
1. Run `cd web-version && npm install multer@^2.0.2`
2. Read each call site identified in Task 1 audit
3. For each call site, apply v2 breaking-change fixes:
   - **fileFilter callback**: v1 used `cb(null, true|false)` — v2 uses `cb(null, true|false)` for accept/reject and `cb(new MulterError(...))` for errors. Verify signatures.
   - **Error class names**: v1 `MulterError` codes changed; check any `instanceof multer.MulterError` and update error code strings if matched
   - **Storage engine**: if a custom `storage` is used, verify it conforms to v2 interface (`_handleFile` and `_removeFile` signatures unchanged, but check return paths)
4. Run `cd web-version && npm ls multer` — confirm `>=2.0.2`
5. Run `cd web-version && npm audit --json` — confirm no multer advisories
6. Run `cd web-version && npm start` — confirm server boots; smoke test the upload route(s) identified in audit (basic POST that hits multer middleware)

**Verification:**
- [ ] `npm ls multer` from `web-version/` shows `>=2.0.2`
- [ ] `npm audit` reports no findings for `multer`
- [ ] Server boots without errors
- [ ] Upload route(s) return non-500 for a valid request (smoke curl or fetch)

## Acceptance Criteria
